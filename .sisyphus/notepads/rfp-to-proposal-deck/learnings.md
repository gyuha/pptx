# Learnings

- Task 1 added additive contracts with strict schema_version literals: corpus.v1, evidence_graph.v1, deck_outline.v1, feedback_patch.v1, batch_manifest.v1, while leaving slidespec.v1 untouched.
- New contracts preserve provenance strictness expectations via required page/evidence/confidence-style fields in evidence-bearing models and deterministic id/hash patterns where applicable.
- Language/image policy metadata now has explicit homes: corpus metadata default_output_language/image_generation_mode, deck_outline language + visual image prompt/model/seed, batch_manifest runtime language/models + per-doc image_generation stats.
- Invalid fixture validation is most actionable when constraints are attached to concrete fields (e.g., links, sections, patches.0.path) rather than model-level validators that surface empty locations.
- Task 2 run-folder uses deterministic document iteration (`relative path` sort), deterministic `batch_id`, and stable per-doc artifact directory `artifacts_root/<batch_id>/docs/<doc_id>` while preserving run-local internals.
- Batch orchestration policy defaults are now explicit in CLI surface: `--model-profile local` and `--continue-on-error true`, with final exit code forced to `1` when any doc is failed/unsupported even if processing continued.
- Batch manifest is validated against `batch_manifest.v1` before write, which guarantees runtime/count/document shape parity between orchestration output and contract schema.
- Task 3 introduced explicit `pipeline.document_registry.v1` at `artifacts_root/<batch_id>/document_registry.json` with deterministic ordering and metadata (`relative_path`, `input_name`, `input_type`, `input_size_bytes`, `sha256`, `doc_id`), and `run-folder` now consumes this registry directly to guarantee stable doc_id mapping.
- Task 4 extends extraction dispatch to `.docx` while preserving existing PDF behavior: both formats emit `extract.v1` payloads accepted by normalize, and corrupt DOCX now deterministically returns `status=unsupported` with `reason_code=invalid_docx_package` (CLI exit code 2).
- Task 5 normalize now emits corpus context with required `source_document_id` at payload and element levels; it uses upstream `input.source_document_id` when provided, otherwise a deterministic fallback `doc_<sha256-prefix>` from extract input identity.
- Task 5 adds deterministic rule-based `requirement_tags` on normalized elements (ordered keyword rules + stable dedupe), preserving existing provenance-required fields and keeping `provenance_coverage` computation unchanged.
- Missing `source_document_id` in normalized payload now fails downstream validation deterministically, while malformed extract payload fail-closed behavior remains field-specific (`metadata` required) during normalize.
- Task 6 added deterministic evidence graph construction in `plan` with stable evidence IDs (`ev_<sha256-prefix>`) derived from normalized element provenance/content and explicit provenance trace (`source_document_id`, `source_page`, `source_block_id`, `source_span`, `evidence`, `confidence`).
- Task 6 planner now fail-closes on orphan claim references via `metadata.claim_reference_map`, producing deterministic explicit error text: `Unsupported planning input: orphan evidence reference for claim '<claim_id>': <evidence_id>.`
- Task 7 introduced an explicit proposal outline stage (`deck_outline.v1`) and deterministic outline-to-slidespec conversion that keeps each emitted slide element provenance (`source_page`, `evidence`, `confidence`) grounded to selected evidence IDs.
- Task 7 enforces fail-closed numeric grounding for outline claims: numeric facts in uncited section-level claims are rejected, and missing mandatory proposal sections still produce deterministic validation errors.
- Task 7 regression fix: `layout_hint` emitted by outline-to-slidespec must be constrained to renderer-supported values only (`title_body_flow`, `title_table_focus`); custom hints like `image_focus` or `table_focus` fail render hard.
- Task 8 evidence confirms `run-folder` now emits one `.pptx` per input document in `--out-dir` while preserving deterministic `doc_id` naming and per-doc artifact trees.
- Task 8 manifests now carry image trace metadata end-to-end (`image_prompt`, `image_model`, `image_seed`, `image_path`) at both run and batch levels, and image generation stats are non-zero on visual slides.
- Task 8 render failure path for missing image API credentials is deterministic: hook error reason is `image_generation_failed` with `phase=render` and credential-specific detail text.
- Task 9 QA gate now adds deterministic trust checks on top of existing gates: `citation_coverage_complete`, `uncited_numeric_fact_absent`, and `contradiction_absent`, with explicit metric counters and failure entries.
- Task 9 uncited numeric detection is grounded by citation-reference heuristics in `SlideElement.evidence`; numeric claims without recognized citation patterns now fail-closed even if other provenance fields are present.
- Task 10 revise loop is safest when staged through temp artifacts (`slidespec/output/qa`) and only promoted to canonical paths after preflight + render + postrender gates pass; this guarantees invalid targets cannot overwrite the existing deck.
- Task 10 follow-up fix: after promoting `output.revise.tmp.pptx.images` to `output.pptx.images`, revise must rewrite `manifest.image_traces[*].image_path` prefixes to canonical paths; otherwise manifests point to deleted temp folders.
- Task 11 added a deterministic runtime model-profile resolver: `local` defaults to mock providers with no cloud credential requirements, while `cloud` fail-fast validates provider wiring plus `OPENAI_API_KEY` before any batch/doc processing.
- Task 11 manifests now carry runtime traceability (`model_profile`, text/image provider+model, `generation_settings_hash`) and per-run image stats include provider/model with `requested/succeeded/failed` counts.
- Task 12 MCP surface now adds deterministic `run-folder`, `analysis-summary`, and `revise` tools with strict tool allowlist dispatch, path policy confinement to workspace root, and pydantic argument schemas (`extra=forbid`) for new operations.
- Task 13 aligned role policy to batch flow with explicit role-scoped MCP allowlists for `run-folder`, `analysis-summary`, and `revise`, while keeping gate enforcement fail-closed and deny-by-default outside assigned stages.
- Task 13 orchestration dry-run now models command-level handoff chains for `run-folder`, `analysis-summary`, and `revise`, including explicit pre/post gate operations in render/revision paths.
- Task 14 regression runbook is deterministic when all outputs stay under `.sisyphus/tmp/task14/*`; this keeps copy-paste verification stable and avoids collisions with prior task artifacts.
- Task 14 batch manifest lookup must use `documents[*].input_file` (not `input_name`) when selecting a target doc for revise in scripted checks.
- Task 14 failure guards are reproducible with two checks: cloud profile without `OPENAI_API_KEY` and revise with `feedback_patch_revise_invalid_unknown_slide.json`; both must exit non-zero with explicit reason text.
